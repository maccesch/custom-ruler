# 3D-printable models: dial caliper and ruler (build123d)

A working rack-and-pinion dial caliper and a plain ruler, modelled
parametrically in [build123d](https://build123d.readthedocs.io). The caliper's
static hardware comes from `caliper_static.3mf`; the beam, black scale inlay
and pinion are generated. Both read in whatever unit you calibrate the web app
to — millimetres out of the box, or the same `UNITS` per `PER_MM` scale the app
in this repo prints.

Default (millimetre) configuration:

```
range            0 – 100 mm
beam             164 mm slab + repeated FreeCAD side profile + 0-end bar,
                 1 mm graduations, numbered every 10 mm
dial             20.00 mm per turn, 100 divisions = 0.20 mm per division
transmission     module 0.637 (2.0 mm rack pitch), 10-tooth herringbone
                 pinion on a cut herringbone rack, 30° helix, single mesh
backlash         0.15 mm nominal, left for the manual slider's mesh preload
```

## In the browser

The Leptos app in this repo generates the same models client-side: open it,
set the calibration, and pick Ruler or Dial caliper in the "3D printable
models" card. The models run on [Pyodide](https://pyodide.org) with the
OpenCascade bindings from [OCP.wasm](https://github.com/yeicor/OCP.wasm),
inside a Web Worker (`public/cad-worker.js`), so nothing is uploaded and the
page stays responsive. When the build finishes, the page hands the visitor a
single 3MF — the static hardware, plus the generated beam and pinion — as a
normal download, so there is nothing to click through in the page.

* `src/cad.rs` embeds the Python in this folder with `include_str!`, so the
  page and the command line always build the identical model.
* `caliper_static.3mf` is a Bambu/Orca project containing the static hardware:
  FacePlate, DialRing, SliderBottom, SliderTop, ArrestLever,
  SliderTopConnectRing, ThumbPinion and SliderBar. The worker fetches it once,
  then adds the generated parts without moving the static objects. The pinion
  goes on the first plate, centred in `SliderTopConnectRing`; the beam + black
  inlay compound goes on plate 3, running diagonally from the upper-left to
  the lower-right of the free area, with its hooked end at the lower-right and
  clear of `SliderBar`. The beam and inlay are one
  compound so they stay in register and can be assigned different filaments;
  the pinion remains its own object.
* The pinion's shaft, journal and bottom socket are static FreeCAD models.
  They ship as `public/cad/pinion_axis.step` and `pinion_cut_out.step`; the
  worker fetches them only when the pinion is being built, and `caliper.py`
  unions the axis and subtracts the cut-out — the same STEPs the command line
  reads from `cad/`.
* The beam's outer profile is a static FreeCAD slice (`beam.step`). It is
  tiled along the beam length and unioned *before* the scale, slot and rack
  cuts, so those features are cut into the new surface. The 0-end bar
  (`top_bar.step`) is unioned at the same stage, with 3 mm of overlap in X,
  so the engraving crosses the joint. The worker fetches both only when the
  beam is built.
* The parameters go over as the same `CALIPER_*` environment overrides the CLI
  takes; the worker re-imports the modules for every run.
Pinning: `PYODIDE_VERSION` and `BUILD123D` at the top of `public/cad-worker.js`
must be bumped together; the OCP.wasm wheels are built for one CPython and
emscripten ABI at a time (currently Pyodide 314.x = CPython 3.14).

## Files

| file | what it is |
|---|---|
| `caliper.py` | the caliper – parameters, parts, assembly, exporter |
| `caliper_static.3mf` | Bambu/Orca project with the static hardware, used as the 3MF template |
| `pinion_axis.step` | pinion shaft and journal, modelled in FreeCAD, fused into the gear |
| `pinion_cut_out.step` | conical socket cut from the bottom of the axis |
| `beam.step` | repeating beam-profile slice, tiled along the beam |
| `top_bar.step` | FreeCAD 0-end bar, unioned into the beam with 3 mm X overlap |
| `ruler.py` | the ruler – bar, rounded corners, hang hole, engraved scale |
| `gears.py` | rack profile + pinion generated by rolling that rack over a blank |
| `scale.py` | tick generation in arbitrary units — a port of `../src/scale.rs` |
| `vecfont.py` | the stroke alphabet the engraving uses (no system font needed) |
| `check.py` | interference/clearance checks and part connectivity |
| `threemf.py` | merges generated meshes into the static project (stdlib only, runs in Pyodide) |
| `export_static.py` | syncs the static template and STEP assets in `public/` with `cad/` |
| `pinion_demo.py` | demo: gear dropped to the axis bottom, rack moved with it |
| `preview.py` | SVG line drawings of the assembly and the loose parts |
| `out/*.3mf` | the supplied static plates, with the pinion on plate 1 and the beam/black-bar compound on plate 3 |
| `out/caliper.step` | assembly at a 25 mm reading, for viewing in any CAD tool |

```bash
python scale.py       # check the tick logic against ../src/scale.rs
python caliper.py       # rebuild out/caliper.3mf + the STEP assembly
python export_static.py # sync the 3MF template and STEPs into public/cad
python pinion_demo.py   # demo pinion with the gear at the axis bottom
python ruler.py         # self-check, then rebuild out/ruler.3mf
python check.py         # collisions, gear mesh, one-solid-per-part
```

The web app prints the same dial face at 1:1 in the "Caliper dial" card
(`src/dial.rs` ports the derivation, `src/app.rs` draws it).

`check.py` reports every interference as zero. The rack/pinion sweep tests a
full tooth pitch from reading 0; it comes out at 0.00000 mm³.

Everything is driven from the parameter blocks at the top of `caliper.py` and
`ruler.py`; any parameter there can be overridden from the environment without
editing the file:

```bash
CALIPER_UNITS=150 CALIPER_PER_MM=10 CALIPER_MAX_UNITS=1500 \
CALIPER_UNIT_NAME=u python caliper.py
```

## Ruler

`ruler.py` engraves the web app's SVG preview into a flat bar, 1:1: the same
`scale.compute_ticks` graduations, hanging from one long edge at the SVG's
minor/medium/major lengths (5 / 7.5 / 9 mm), with the major values rotated
along the bar exactly where the SVG puts them, using the label size the app
passes as `CALIPER_FONT_MM`. The ticks run right up to the bar's edge and the
blank margin sits past the numerals; by default the bar also starts on the
centre of the 0 tick, so its left edge is the zero line ("Margin at 0" in the
app, or `CALIPER_ZERO_MARGIN=1`, keeps the SVG's padding before the 0 tick
instead). The bar is 2 mm thick by default (the app's Thickness field, or
`CALIPER_THICK`) and carries a Ø4.5 mm hanging hole past the last graduation;
it prints flat, engraved face up. Grooves are 0.5 mm wide and 0.45 mm deep
(the SVG strokes are hairlines, too fine to print), the width follows the
longest label (at least 18 mm), and the hole keeps 2.5 mm of material to the
end of the bar. `python ruler.py` self-checks the envelope, the through-hole,
the rounded corners and the engraving before writing `out/ruler.3mf`:

```bash
CALIPER_UNITS=150 CALIPER_PER_MM=10 CALIPER_MAX_UNITS=1500 \
CALIPER_UNIT_NAME=u CALIPER_FONT_MM=2.5 python ruler.py
```

## Text

Engraved numerals are drawn with `vecfont.py`, a small built-in stroke
alphabet, not with build123d's `Text()`. `Text()` needs a font installed on
the machine: "Arial" does not exist under Pyodide, and build123d's bundled
single-line font raises on several of the strings this model engraves. A
stroke alphabet is also what engraving wants — uniform, printable channels
rather than filled outlines.

## Units

Both models are calibrated the same way as the web app: **`UNITS` counted over
`PER_MM` millimetres**, plus `MAX_UNITS` for where the scale ends. Those three
numbers size everything else — the ruler's length, the caliper's beam, gear
ratio, dial, even the jaw thickness; the ruler additionally follows the label
size (`FONT_MM`).

| parameter | meaning |
|---|---|
| `UNITS` / `PER_MM` | calibration pair; `UNITS_PER_MM = UNITS / PER_MM` |
| `MAX_UNITS` | scale ends here; physical range is `MAX_UNITS / UNITS_PER_MM` mm |
| `UNIT_NAME` | printed on the paper dial, passed through to the 3D build |
| `FONT_MM` | ruler: label cap height — the app passes its label size |
| `THICK` | ruler: bar thickness — the app passes its Thickness field |
| `ZERO_MARGIN` | ruler: keep the SVG's padding before the 0 tick |
| `TARGET_MM_PER_REV` | how much travel one needle turn should be, in mm |
| `MODULE_TARGET` | tooth size to aim for; 0.64 ≈ a 2 mm rack pitch |
| `UNITS_PER_REV`, `PINION_TEETH` | `None` = chosen for you; set to override |

What gets derived:

* **Beam ticks** come from `scale.compute_ticks`, a port of `../src/scale.rs` —
  the same 1/2/5 × 10ⁿ step snapped to ~1.5 mm spacing, medium at 5×, major at
  10× and numbered. `scale.py` self-tests against the worked examples in the
  Rust module, so the printed caliper and the printed ruler agree.
* **Units per turn** snaps to a nice 1/2/5 value near `TARGET_MM_PER_REV`, so
  the dial is numbered in round units. The tooth count is then picked from
  8–16 to land the module near `MODULE_TARGET`; `caliper.py` warns if the
  result drops below 0.45 (too fine for FDM).
* **Dial divisions** take the finest nice unit step that keeps at most
  `MAX_DIAL_DIVISIONS` ticks, so they never crowd below ~1.2 mm apart. The
  face itself is paper: the web app draws the disc at 1:1 with tick ring,
  numerals, unit label, bore cut guide and bezel-notch guides.
* **Inside offset** — reserved: the manual slider this caliper builds against
  carries no engraved inside offset, so none is derived.
Two worked examples:

```
UNITS=1  PER_MM=1  MAX_UNITS=100          UNITS=150 PER_MM=10 MAX_UNITS=1500
range   0-100 mm = 100 mm                 range   0-1500 u = 100 mm
ticks   every 1 mm, numbered every 10     ticks   every 20 u, numbered every 200
dial    20 mm/turn, 100 x 0.2 mm          dial    200 u/turn, 100 x 2 u
gears   module 0.637, 10 teeth            gears   module 0.531, 8 teeth
```

Both pass `check.py` unchanged. (`INSIDE_OFFSET` / `FIX_JAW_T` references
elsewhere in the repo history are stale: the manual slider this caliper
builds against has no engraved inside offset.)

## How it works

The beam is a single 4 mm slab with a slot along X through it, closed at both
ends. The rack sits on the slot floor across the full thickness (rack face
width = beam thickness), teeth pointing up (+Y), and the main scale is
engraved into the beam's face, hanging from the top edge — rack and scale on
opposite sides of the beam.

The slab's outer profile comes from `beam.step`, a FreeCAD slice of the
profile. It is periodic with period π and spans 5π, so it tiles seamlessly at
its own length along X; the union happens before the scale, slot and rack
cuts, so those features are cut into the new surface. The slice is shifted
from the FreeCAD beam frame (y centred, z −4…0) to this model's frame
(y 0…`BEAM_H`, z 0…`BEAM_T`). Its rails add 1.333 mm to each long edge, so the
finished beam is 20.67 mm across. The 0-end bar uses the same frame mapping,
is aligned with the 18 mm beam core and the beam's front, and has its right
end pushed 3 mm into the beam (x 0…3) so the joint is a real overlap. The
profile pattern is extended left to the bar's outer end, so the rail finishes
flush with it. The scale cut happens afterwards, so the 0 label runs across
the joint. The pinion axis sits in the beam's y-centre; the pinion's journal
and shaft run in the manual slider and front plate (modelled outside this
repo), and the shaft reaches forward into the dial housing. +X travel rolls
the pinion clockwise.

At reading 0 the axis is 40 mm down the beam: the manual slider's top face is
40 mm from it, and 40 mm is two needle turns, so the pinion sits at rotation 0
there. The rack teeth are phased to that (a tooth centred under the axis at
`PIN_X`), which lets the needle be pressed onto the hex drive pointing at the
dial's 0 without fighting a tooth off the hex. Because the axis never goes
left of that position, the slot opens just past the pinion's tip circle there:
the first ~35 mm of the beam are closed, like the tail past the last tooth.

One turn of the pinion is `π · module · teeth` = one `UNITS_PER_REV` of travel,
so the dial is numbered in round units. Read whole divisions off the beam at
the left edge of the slider and the fraction off the dial.

Tooth size and dial resolution trade directly against each other: the pitch
circumference *is* one revolution of travel, so doubling the tooth size halves
the dial resolution. At the default 2.0 mm rack pitch and 1.9 mm tooth depth
that is about five extrusion widths per flank on a 0.4 mm nozzle — comfortable.
Halving `TARGET_MM_PER_REV` doubles the dial resolution and wants a
0.25–0.3 mm nozzle.

**Herringbone.** Rack and pinion are both chevrons at a 30° helix. Everything
is defined in the transverse plane — the 2D rack and the 2D generated pinion
above — and the third dimension is a pure skew: the rack teeth step ~2.2 mm in
X from the apex to each end (half the 7.6 mm face width at 30°), and the
pinion is twisted by the matching ~40° = 2.2 mm / pitch radius. (The pinion
rides on top of the rack, so its chevron twists the standard way for a
pinion riding on top.) Any transverse slice therefore shows the same verified 2D
mesh. The overlap in the chevron raises the contact ratio, which smooths out
the tooth-to-tooth ripple a 10-tooth pinion would otherwise show, and the V
locates the pinion axially with no thrust face.

The pinion teeth are **generated**, not drawn: `gears.pinion_profile` rolls the
mating rack cutter over a blank and takes the envelope. At 8 teeth the flank
runs well below the base circle, and a drawn involute with a radial root fouls
the rack – `check.py` catches exactly that. The sweep has to run ±1.5 pitches
or the tooth tips are never trimmed.

The shaft and journal are not generated: they are a static FreeCAD model
exported to `pinion_axis.step` and fused into the gear in `pinion()`, and a
second STEP (`pinion_cut_out.step`) is subtracted to leave the conical socket
in the bottom of the axis. The part that gets printed and exported is still
one solid. Both STEPs are in the part's local frame (Z along the shaft, z = 0
at the gear's back face).

## Pinion mounting

The pinion is generated here, but its bearing is not: the journal and shaft
run in the manual slider and front plate, which are modelled outside this
repository. The beam only has to clear it — the shaft slit carries 0.35 mm of
play each side for the slider's preload travel, and the slot opens wide enough
for the whole gear.

The teeth are cut loose (0.15 mm backlash) and the rack and pinion roots run
deep (1.9 and 1.85 module), so there is room for the slider's preload to close
the mesh without anything bottoming out.

## Printing

| part | qty | orientation (as exported) | notes |
|---|---|---|---|
| `ruler` | 1 | flat, engraved face up | no supports |
| `beam` + black bar | 1 + 1 | plate 3, diagonal, flat, engraved face on the bed | one compound; white beam, black inlay |
| `pinion` | 1 | plate 1, centred in `SliderTopConnectRing` | separate object; filament 2; no supports, no brim – the Ø8 gear sits flat on the plate |
| paper `dial_face` | 1 | print the "Caliper dial" card at 100% | cut on the solid circle, bore the dashed hole |
| static hardware | – | plates 1–3, as arranged in `caliper_static.3mf` | FacePlate, DialRing, SliderBottom, SliderTop, ArrestLever, SliderTopConnectRing, ThumbPinion, SliderBar |

No part needs support. Settings that matter:

* 0.4 mm nozzle is comfortable for the 2.0 mm rack pitch; a 0.25–0.3 mm nozzle
  still helps the beam graduations (1.2 mm tick spacing on the paper dial
  prints fine on any printer).
* 0.1–0.15 mm layers, 4 perimeters, ≥40 % infill on the beam.
* PETG or ASA over PLA – PLA creeps and the mesh preload relaxes.
* The generated 3MF keeps the static plates as supplied: the pinion joins
  plate 1 and the beam joins plate 3. The beam is 181.5 mm over the 0-end bar
  (164 mm of scale) and 74.4 mm across; it is placed diagonally in the free
  area beside `SliderBar`.
* Paint-fill the engraved beam scale (0.45 mm deep) or do a filament change
  two layers below the top surface. The dial needs no paint — it is paper.

Every part meshes to well under 1 MB; `check.py` fails them above 5 MB. That
guard exists because a twisted extrusion of a boolean-generated outline can
silently explode — the herringbone pinion first came out as a 67 MB, 1.35 M
triangle STL until the tooth outline was decimated (see `gears.simplify`).

Build times, on a laptop: 0–7 s a part (the patterned beam is the slowest),
about 25 s for the whole caliper.
Getting there took four fixes, all in the same place — the generated tooth
outline is ~1800 hair-thin edges, and everything downstream scales with it:

| | |
|---|---|
| decimate the outline (`gears.simplify`) | the 67 MB STL, and most of the sweep cost |
| walk the wire by hashed endpoints (`gears._chain`) | `Wire.order_edges()` compares every edge with every other: 21 s |
| fold `HELIX_SHAVE` into the cutter | an `offset()` turns every corner into its own arc, +50 % edges |
| `fuse(glue=True)` on the chevron halves | they meet on one coincident plane, which is what glue is for |

Hardware: 3 × M3 × 10 countersunk self-tapping screws (plastic/chipboard
screws are ideal) into the manual front plate's 2.5 mm pilot holes.

## Assembly

1. Drop the pinion into the beam slot, teeth meshed with the rack, and fit the
   manual slider so the shaft enters its bore.
2. Fit the manual front plate over the shaft.
3. Cut the paper dial out, bore the dashed centre hole, and drop it into the
   recess, notches anywhere.
4. Press the needle onto the hex drive on the shaft, pointing at 0.
5. Snap the bezel over the wall: its three lugs go through the dial's notches,
   so turning the bezel now turns the paper dial.
6. Thread in the lock screw from the top.

Optional window: a Ø43 disc cut from 0.5 mm PET sheet drops in under the bezel
lip before the bezel is snapped on.

## Zeroing and use

Set the slider to 0, then rotate the bezel until 0 is under the needle. Read
the beam at the slider's left edge for whole divisions and the dial for the
rest.

## What to expect

This is a printed instrument, not a Mitutoyo. Realistically ±0.2 mm. With the
mesh play taken up by the slider's mounting, hysteresis is down to friction
and the stiffness of the printed frame rather than lost motion in the gear.
The dial resolves 0.2 mm; that is the resolution, not the accuracy.

For twice the dial resolution, set `TARGET_MM_PER_REV = 10`. That halves the
tooth size to a 1.25 mm pitch and really wants a 0.25–0.3 mm nozzle;
everything else follows automatically.
